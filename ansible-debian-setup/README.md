# Оптимизированные Ansible-скрипты для настройки Debian-систем

В этой директории находятся оптимизированные скрипты и Ansible-роли для автоматической настройки Debian-систем, настройки NFS, резервного копирования и других задач.

## Основные файлы и директории

- **roles/** - директория с Ansible-ролями
  - **common/** - общие настройки для всех серверов
  - **nfs/** - настройка NFS-сервера и клиента
  - **backup/** - настройка резервного копирования
  - **sync/** - синхронизация файлов между серверами
  - **docker/** - установка и настройка Docker
  - **users/** - управление пользователями
  - **database/** - настройка базы данных
  - **network/** - настройка сети

- **unified-nfs-manager.sh** - универсальный скрипт для управления NFS
- **backup-manager.sh** - универсальный скрипт для управления бэкапами
- **auto-configure.sh** - универсальный скрипт для автоматической настройки с использованием Ansible

## Как использовать

### Управление NFS

Универсальный скрипт `unified-nfs-manager.sh` заменяет отдельные скрипты для монтирования и оптимизации NFS. Скрипт автоматически определяет все доступные диски на сервере.

```bash
# Монтирование NFS шар (автоматически определяет все доступные диски)
sudo ./unified-nfs-manager.sh mount

# Оптимизация NFS параметров
sudo ./unified-nfs-manager.sh optimize

# Перемонтирование с оптимизированными параметрами
sudo ./unified-nfs-manager.sh remount

# Проверка статуса NFS
./unified-nfs-manager.sh status

# Справка
./unified-nfs-manager.sh help
```

### Управление бэкапами

Универсальный скрипт `backup-manager.sh` заменяет отдельные скрипты для создания и ротации бэкапов.

```bash
# Создание нового бэкапа конфигурации
./backup-manager.sh create

# Создание полного бэкапа системы
./backup-manager.sh create --full

# Ротация бэкапов (удаление старых)
./backup-manager.sh rotate

# Восстановление из бэкапа (интерактивно)
sudo ./backup-manager.sh restore

# Проверка статуса бэкапов
./backup-manager.sh status
```

### Автоматическая настройка с Ansible

Универсальный скрипт `auto-configure.sh` заменяет отдельные скрипты для настройки с использованием Ansible.

```bash
# Настройка NFS-сервера и клиента
./auto-configure.sh setup-nfs

# Настройка системы резервного копирования
./auto-configure.sh setup-backup

# Полная настройка системы
./auto-configure.sh setup-all
```

## АВТОМАТИЗАЦИЯ ПОЛНОСТЬЮ В ОДНУ КОМАНДУ

Для полной автоматизации всего процесса настройки достаточно выполнить одну команду:

```bash
sudo ./auto-configure.sh setup-all
```

Эта команда последовательно выполнит:
1. Настройку NFS-сервера и клиента
2. Автоматическое монтирование всех найденных NFS дисков
3. Оптимизацию параметров NFS для максимальной производительности
4. Настройку системы резервного копирования
5. Создание первого полного бэкапа

## Замечания по оптимизации

1. **Унификация скриптов**: Вместо множества отдельных скриптов с дублирующейся функциональностью, теперь используются три универсальных скрипта с четко определенными функциями.

2. **Автоматическое определение дисков**: Скрипт `unified-nfs-manager.sh` автоматически определяет все доступные диски через SSH, showmount или прямое сканирование. Больше не нужно вручную указывать список дисков!

3. **Модульность**: Каждый скрипт разделен на функции, которые можно легко модифицировать или расширять.

4. **Логирование**: Добавлено подробное логирование в каждом скрипте для удобства отладки.

5. **Проверки**: Добавлены проверки перед выполнением критических операций, что повышает надежность.

6. **Многоуровневое обнаружение ресурсов**: Если один метод обнаружения дисков не работает, скрипт автоматически переключается на другие методы.

## Пример настройки системы с нуля

```bash
# Одна команда для полной настройки системы
sudo ./auto-configure.sh setup-all

# Проверка результатов
./unified-nfs-manager.sh status
./backup-manager.sh status
```

Это обеспечит полностью автоматизированную настройку системы с минимальным вмешательством пользователя.

## Интеграция с существующими системами

Для интеграции с существующими системами не требуется особых действий, достаточно запустить соответствующие команды для необходимых компонентов.

## Примечания

Для большинства операций требуются права root. Используйте `sudo` при необходимости.
